# My Download 📥

Android 影片瀏覽與下載 App（Kotlin + Jetpack Compose）。

> **目前主要儲存庫：** [jimmy0933/my-download](https://github.com/jimmy0933/my-download)。
> 這是從既有功能規格重建的新專案。舊 GitHub 帳號的原始碼目前無法由此連線讀取，並非原始 Git 歷史的逐位元複製。

## 功能

- Android WebView 直接瀏覽 AV01，網站縮圖、連結、播放器以及全螢幕操作
- 對目前可見且有影片連結的縮圖，用**原生浮動下載按鈕**提供快速下載，不改動網站 DOM
- 影片詳細頁固定「下載此影片」，按鈕直接打開畫質選擇
- MP4 / 未加密 M3U8 解析與下載，HLS 多畫質選擇
- AV01 的公開影片資訊、Geo、Manifest、CDN-access API 解析（需網站正常授予權限；API 可能變動）
- MP4 背景下載、HLS 分段下載、下載紀錄、進度、暫停及續傳
- HLS 盡可能轉成可快轉的 MP4；若無法無損重封裝則保留原片段檔
- 「設定」可以選擇下載資料夾，使用 Android 系統資料夾選擇器並保存授權
- 「設定」可以開關輕量廣告阻擋：攔截常見廣告網域與外站彈出頁
- GitHub Actions：測試、簽章、檢查 APK 簽名、更新最新 Release，刪除較舊的 Release

## 使用

開啟 App，在「瀏覽網站」瀏覽影片，點縮圖旁的 **↓ 下載**，或進入影片頁按 **下載此影片**，然後選擇畫質。下載進度在「下載管理」。

亦可在下載管理手動貼入 HTTPS 網址。

下載位置預設為 `Movies/MyDownload`。要更改請開啟「設定 → 下載位置」，選擇系統允許存取的資料夾；新的下載任務會記住設定當下的路徑。Android 11 以上可能無法選擇根目錄或整個 Downloads，建議使用其子資料夾。

廣告阻擋預設關閉。開啟後會嘗試阻止常見廣告網域與第三方彈出頁；若網站變更導致部分內容不可用，可以關閉。

## Android 與串流限制

- Android 10（API 29）以上
- 只下載有權保存的無 DRM、未加密影片。不繞過登入、付費、DRM 或網站的存取限制。
- 不保證 AV01 每個影片或畫質都可解析。網站的 API、影片來源或下載權限可能隨時變更。
- 非所有縮圖都一定有可辨識的 `/video/` 連結；這些縮圖可能不顯示浮動鈕。可改用詳細頁下載。
- HLS 的加密、BYTERANGE、DISCONTINUITY、部分 fMP4 等可能不支援；不能無損封裝時可能留下 TS/原始片段格式，快轉可能受限。
- 續傳依賴伺服器 HTTP Range 或完整 HLS 分段；令牌過期後可能需重新解析。
- 必須有足夠手機儲存空間。部分影片在下載時會暫存片段與輸出檔。
- 重新安裝或從其他 applicationId 切換時，不會自動搬移舊 App 的下載紀錄。

## 自訂資料夾權限修復

如果下載時看到「自訂資料夾沒有權限」：

1. 更新到最新 APK。
2. 開啟 App → **設定** → **選擇資料夾**，再次選擇要儲存影片的子資料夾。
3. 在 Android 的系統視窗按下 **使用這個資料夾／允許**。
4. App 會立即進行短暫的建立檔案與寫入測試，成功後顯示綠色提示。
5. 若先前已有因資料夾授權失敗的任務，到 **下載管理** 按 **繼續**，已完整下載的 MP4 優先直接重試儲存，不必重新抓取影片。

修正後不再以持久化 URI 的字串完全相同作為權限判斷，而是由 Android 的 DocumentsProvider 實際驗證。
若仍不能寫入，改選手機內部儲存的自建子資料夾，例如 Movies/MyDownload 或其他支援寫入的資料夾。已完成的影片不會自動搬移。


## 下載卡在 96% 的修復（2026-11-04）

- HLS 影片在 94% 之後進入 MP4 整理階段。新版會顯示整理階段的進度，並定期檢查暫停指令。
- 整理階段不再清空下載分段的 checkpoint 和 bytes；已完整下載的原始影片會記錄為 readyToFinalize。
- 重開 App 或按下「繼續」時，若原始片段已在本機，直接嘗試完成整理和儲存，不必重下載片段。舊版已到 96% 的暫存檔也會嘗試恢復。
- MP4 重新封裝不再設定時間上限。由使用者暫停或格式／儲存錯誤中止；若不支援封裝，會保留原始 HLS 串流。
- 寫入儲存位置時會顯示已寫入的 MB 數，並在每個區塊檢查暫停。
- 快速連按暫停與繼續時，若舊任務還未停止，會將新的開始請求排隊，避免直接忽略。
- 對卡住的 HLS 整理畫面新增「重試整理」，新版優先使用手機上已下載的原始影片。

請更新最新 APK，進入「下載管理」測試原本 96% 的任務。若暫存檔已被系統清除，仍需要重新下載；新版不會恢復已消失的檔案。


## 已下載 100% 但顯示「MP4 整理逾時」

進度 100% 並顯示「已保留原始串流」，代表下載完成，但原始串流沒有成功建立 MP4 快轉索引。影片可嘗試播放，但部分快轉／拖動進度條功能可能不正常。

新版修復方式：

1. 打開「設定 → 影片修復」，可以開關 **下載完成後自動修復 MP4**。預設關閉，新加入的 HLS 任務才會套用。
2. 想手動修復時，在同一頁的 **手動修復已下載影片** 選取影片並按 **開始修復 MP4**。直接讀取手機上已保存的影片，不必重新下載。
3. 這一頁會顯示讀取、重新封裝與儲存進度，也能按 **暫停修復**。
4. 新 MP4 已儲存且驗證可讀、下載紀錄更新成功後，**自動刪除舊影片**。成功後到「下載管理」按播放即可。若修復中斷或失敗，原始檔不會被刪除。

修復需要足夠的暫存空間，約為原始影片大小的兩倍再加一些額外空間。若 Android MediaExtractor / MediaMuxer 不支援來源的編碼或封裝，修復可能失敗，這時會保留原始影片。若新影片成功但 Android 拒絕刪除舊檔，App 會明確提示清理失敗。

自動及手動 MP4 封裝都不再依時間停止。大型影片會持續整理直到完成、使用者暫停，或發生實際錯誤。修復結果另存 `_fixed.mp4` 並驗證後，下載紀錄改指向新影片，再嘗試刪除舊檔。


## 多網站瀏覽器（第 1、2 階段）

- 瀏覽分頁已改成 **多 WebView 分頁瀏覽器**，不再限定 AV01。網址列可輸入任何 HTTP(S) 網站，或直接輸入關鍵字使用 Google 搜尋。
- 可在同一個 App 開啟 x.com、AV01、一般新聞或影片網站。頁面中的正常連結、登入頁導覽也會保留在 App 內；使用者點擊產生的新視窗會以新分頁開啟。
- 分頁列可新增、切換、關閉分頁（最多 12 個），右側新增分頁按鈕固定顯示。首頁提供 X、AV01、Google 快捷入口及最近的書籤。
- 網址列的書籤按鈕收藏／取消收藏目前網站。「我的書籤」支援開啟、刪除、重新命名、自訂分類、按分類篩選、名稱／新增時間排序與搜尋；瀏覽紀錄支援搜尋、開啟、全部清除。
- App 重新開啟後會恢復原本的分頁 URL、標題、目前分頁，以及永久保存的書籤與瀏覽紀錄。WebView 原生返回歷史不會跨 App 重啟完整保存。
- 為減少 Android 記憶體佔用，最多只保留四個正在使用的 WebView；較舊分頁在切換回來時重新載入最後 URL，舊頁面表單或未提交的內容不保證保留。
- 原有 AV01 影片縮圖旁的原生下載按鈕、影片詳細頁下載鈕、下載清單、儲存資料夾、自動或手動 MP4 修復、廣告阻擋設定均保留。
- **本次先實作瀏覽器及書籤。X 的影片辨識和下載屬後續階段**：目前可瀏覽及收藏 X 貼文，但不保證 X 影片有可下載來源；直接 MP4／未加密 M3U8 網址可沿用下載器解析。
- 某些網站可能拒絕 Android WebView 登入或播放；第三方 OAuth 登入、受保護串流和 DRM 不保證支援。
